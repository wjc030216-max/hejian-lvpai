# 二期角色坑位与一人体验（2026-10-08）

模板有几个角色，就展示几个坑位，不另设主角。角色数量以基础元数据 module_1.actor_count 和 character_settings 为准，两者不一致时拒绝使用。module_2 的“3–4人”是分类信息，不能决定上传数量。

## 游客操作

1. 首页自动播放模板，上下滑动；“想拍几人同框”表示成片人数，不是现场游客数量。
2. 点击拍摄同款，进入上传页。多人模板显示“多人同框／一人体验”；单人模板直接上传。
3. 多人同框：每个坑位上传对应游客照片，全部检查通过后才能开始。
4. 一人体验：游客明确选择一个“我演这个”的坑位，只需这一张照片检查通过。其他坑位显示模板角色图及“使用模板人物”。不自动选第一位，不复制游客的脸到其他位置。
5. 切换模式保留草稿照片，但未选中位置的游客照片不会参与本次生成。下单后锁定模式及角色，不能再更换。
6. 开发环境跳过付款后自动制作；定妆照存储完成后进入视频制作。定妆照本身不作为视频模型输入。

## 数据与接口

| 内容 | 保存位置或来源 |
|---|---|
| 拍摄模式 | 制作记录 participation_mode：multi / single |
| 一人体验选中位置 | selected_person_uid，必须属于本模板；未选定时不可下单 |
| 每个位置的身份 | person_uid、character_id，与模板角色、服装、照片保持对应 |
| 游客照片 | 原有草稿角色字段，保留上传及检查记录 |
| 模板人物 | 服务端从已确认的模板素材读取，客户端不能提交替代地址 |
| 定妆照和视频共用的角色对应表 | 用户角色标记 user_face；模板角色标记 template，独立保存 template_face_url |
| 模式修改接口 | POST /api/v2/projects/{id}/participation，参数 mode、person_uid；不创建生成任务 |

一人体验只为游客生成换装参考，其他角色使用对应模板角色图。视频沿用定妆照任务保存的角色对应表，提交每个角色的人物参考、造型参考及场景；不提交展示用定妆照。普通多人模式缺照片仍报错，不自动补人。

## 元数据筛选

目录读取模板原始基础元数据中的人数、名称、宣传语、角色、关系、风格，以及 recommendation_persona 中的推荐性别、推荐年龄、景区。性别、年龄选项根据现有数据生成；“不限”的模板匹配相应筛选，不凭空给具体模板补性别年龄。

单人模板关系标签中的“男／女”不再出现在同行关系中。更换景区清除其他筛选；更改某一步清除后续条件；可跳过、单独取消条件。筛选用于选模板，上传页不重复询问。

## 验证与边界

自动检查覆盖第二、第三坑位、草稿恢复、未选角色禁止下单、普通模式缺照片、模板人物来源校验、定妆照到视频对应关系、筛选及接口状态。云端调用在测试中替换，不产生生成费用。页面经过 WXML/WXSS 编译及多尺寸布局检查；仍需在微信开发者工具验证实际交互，并由游客主动提交一笔真实生成验证视觉效果。

《漓江寻宝小队》的宣传语写“三位好友”，角色却为孩子、父亲、母亲，这是原模板内容冲突，未擅自修改。
