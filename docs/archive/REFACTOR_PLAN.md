# 二期本地重构建议

本地开发现在只编译 `client/pages/phase2`，业务入口已经从一期页面和一期筛选逻辑中独立出来。清理目标是让模板元数据成为唯一事实来源，让制作会话成为唯一状态边界，让 AI Provider 只在服务端编排层出现。

## 已完成的清理

- 删除 qiniu、KIE、t2i、移动云图片入口和重复服务管理脚本。
- 图片只保留 Seedream 5.0 Pro；人脸只保留阿里云 FaceBody；视频继续走 Seedance。
- 删除二期 `PUT /roles` 和手工 `POST /advance` 模拟接口。
- 删除角色与造型独立页，模板选择后直接按 `character_settings` 进入照片上传。
- 删除二期前端旧的“人数、关系、性别、年龄、收藏”状态字段和一键填充照片按钮。
- 删除重复的模板适配器和按分组重复渲染模板区；全部模板页只保留筛选结果横向浏览。
- 二期前端 app 配置只注册二期页面，避免误进入一期页面。

## 当前保留边界

一期后端服务文件仍作为已上线版本的回滚参考，不参与本地二期小程序编译。二期前端只依赖 `/api/v2`；AI 服务内部继续使用稳定的 `/api/v1` Provider 接口，避免让游客端直接接触密钥或云厂商参数。

## 建议的下一次重做

1. 将 `server/phase2/phase2_app.py` 拆为 `templates`、`projects`、`orders`、`orchestration` 四个模块，控制器只做参数校验。当前已先落地独立的 `orchestrator.py` 和状态推进。
2. 用 MySQL 保存模板版本、制作会话、角色照片、订单和任务快照；Redis 只做进度缓存和幂等锁。
3. 支付成功回调触发编排：FaceBody → Seedream 角色三视图 → 多人定妆照 → Seedance 视频；每一步写任务状态，失败可重试。当前编排器已串接定妆照、分镜和视频 HTTP 任务。
4. 小程序只保留五个业务入口：景区/热门模板、全部模板、角色照片、制作进度、作品/权益；模板详情使用抽屉或半屏预览，不再新增跳转页。
5. 真机测试前增加一套测试模板资源检查，保证封面、示例视频、场景图和角色服装图都是公网可访问 URL。

这套结构完成后，换模板只需要改元数据和资源，不再改页面逻辑；换 AI Provider 只改服务端适配器，不再改小程序。
