# 二期专用数据模型与接口设计（以三份测试模板为准）

这份设计只覆盖二期：选模板、上传人物照片、生成并展示定妆照、用户确认后生成竖屏视频、保存作品。没有把一期的分镜图片、旧支付流程或旧的奇怪页面带进来。

## 1. 先锁定已经核实的事实

### 1.1 三份模板实际内容

| 模板 | 景区 | 人数（角色数量） | 角色顺序 | 类型 | 标签 | 实际用于视频的文字 |
|---|---|---:|---|---|---|---|
| 江影御剑行 | 漓江 | 1 | 男主角A：修仙男主 | 奇幻穿越 | 男 | `5-分镜提示词.txt`，9秒 |
| 漓江心动之旅 | 漓江 | 2 | 女主角A：温柔妻子；男主角A：稳重丈夫 | 休闲旅拍 | 夫妻 | `5-分镜提示词.txt`，15秒 |
| 漓江寻宝小队 | 漓江 | 3 | 男主角A：孩子；男主角B：父亲；女主角A：母亲 | 动作冒险 | 三口之家 | `5-分镜提示词.txt`，11秒 |

三份样例都只属于漓江，当前不能从样例推导银子岩或其他景区的模板。

### 1.2 模板文件的用途

| 文件 | 二期用途 | 处理要求 |
|---|---|---|
| `1-基础元数据.txt` | 模板名称、宣传语、人数、角色、类型、标签、景区 | 原文保存；人数以角色数组为准 |
| `2.1-场景设定图-*` | 生成时的场景参考 | 保存原图尺寸和文件地址 |
| `3.x-角色设定图-*` | 角色外形参考 | 按 `character_id` 绑定，不能按上传先后绑定 |
| `4.x-道具设定图-*` | 可选道具参考 | 是否送入视频请求必须由模板配置明确，不能自动全塞 |
| `5-分镜提示词.txt` | **视频动作、镜头、对白提示词** | 文件名虽然写“分镜”，二期只把其中的文字作为视频提示词，不生成分镜图片 |
| `6-封面图.*` | 模板卡片和详情页封面 | 只展示，不作为用户输入 |
| `7-成片案例.*` | 单击模板时播放的竖屏示例 | 记录真实宽高、时长，不把文件名错别字当成业务字段 |
| `8-模板配乐.*` | 模板音乐资料 | 是否后期混音要有明确配置；不能因为有音乐文件就重复叠加 |
| `9.x-角色服装图-*` | 定妆照和角色参考 | 按角色编号绑定 |
| `10-模板分镜图.png` | 历史打包参考图 | 二期不提交给生图或视频接口 |
| `11-定妆照提示词.txt` | 定妆照生成文字 | 必须使用文件中的模板提示词，并替换角色标记；不能用代码里的通用提示词覆盖它 |

### 1.3 样例存在的冲突，不能静默修正

| 冲突 | 处理方式 |
|---|---|
| 元数据都写15秒，但三个视频文字时长为9、15、11秒 | 同时保存“标注时长”和“提示词时长”；上线前由业务确认最终时长 |
| 三口之家写“3-4人”，角色数组只有3人 | 生成时按角色数组的3人；“3-4人”只作为展示标签，不能让用户多传第4人 |
| “三位好友”与孩子、父亲、母亲角色不一致 | 保留原宣传语；不自动改成“三口之家” |
| 单人模板没有 `person_uid` | 导入时生成稳定的角色槽位编号，保留原 `character_id`；游客不需要再选角色 |
| 单人宣传语说青衫，提示词写白浅蓝镶边长袍 | 原文都保留；后台标记为待核对，不擅自改词 |

## 2. 二期数据表

下表中的“文字”“数字”“真假”“时间”“列表”是给开发人员看的字段类型说明。每张表都有一个内部编号，编号不能用数组下标代替。

### 2.1 景区表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 景区编号 | 文字 | 是 | 例如 `lijiang`，由后台维护 |
| 景区名称 | 文字 | 是 | 例如“漓江” |
| 封面地址 | 文字 | 否 | 首页景区卡片图片 |
| 是否展示 | 真假 | 是 | 控制是否出现在小程序 |
| 排序号 | 数字 | 是 | 首页排列顺序 |
| 创建时间、修改时间 | 时间 | 是 | 追踪配置变化 |

当前样例只能导入“漓江”。没有真实数据的景区不建假记录。

### 2.2 模板表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 模板编号 | 文字 | 是 | 永不重复，详情和制作会话都引用它 |
| 当前版本编号 | 文字 | 是 | 模板内容变化后生成新版本 |
| 景区编号 | 文字 | 是 | 对应景区表 |
| 模板名称 | 文字 | 是 | 来自 `video_name` |
| 宣传语 | 文字 | 否 | 来自 `story_hook` |
| 准确人数 | 数字 | 是 | 来自 `module_1.character_settings` 的数量 |
| 展示人数标签 | 文字 | 否 | 来自 `module_2.actor_count`，只用于显示 |
| 视频类型 | 文字 | 否 | 来自 `video_genre` |
| 二级标签列表 | 列表 | 否 | 来自 `relationship_tags` |
| 标注时长 | 数字 | 否 | 从 `video_specification` 解析，例如15 |
| 提示词时长 | 数字 | 否 | 从 `5-分镜提示词.txt` 的 `total_seconds` 读取 |
| 推荐性别、推荐年龄 | 文字 | 否 | 仅模板推荐文案，不是游客真实资料 |
| 是否可用 | 真假 | 是 | 模板审核完成后才可被推送 |
| 热门排序值 | 数字 | 否 | 只用于后台排序；没有真实统计时留空 |

不保存“已有几万人选择”这类假数值。需要宣传时使用后台真实选择次数，并单独标注统计截止时间。

### 2.3 模板角色槽位表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 槽位编号 | 文字 | 是 | 稳定编号，例如 `role-1` |
| 模板版本编号 | 文字 | 是 | 防止模板改版后角色错位 |
| 原角色编号 | 文字 | 是 | 例如“男主角A” |
| 原人物编号 | 文字 | 否 | 有则保存 `person_uid` |
| 原来源编号 | 文字 | 否 | 有则保存 `source_character_id` |
| 显示名称 | 文字 | 是 | 例如“温柔妻子” |
| 显示顺序 | 数字 | 是 | 严格按元数据数组顺序 |
| 角色图地址、服装图地址 | 文字 | 否 | 对应3.x、9.x文件 |
| 是否需要照片 | 真假 | 是 | 二期默认是真；以后允许纯虚拟角色模板 |

### 2.4 模板资源表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 资源编号 | 文字 | 是 | 资源的稳定编号 |
| 模板版本编号 | 文字 | 是 | 资源属于哪个版本 |
| 资源类别 | 文字 | 是 | 封面、示例视频、场景、角色图、服装、道具、音乐、定妆提示词、视频提示词 |
| 绑定槽位编号 | 文字 | 否 | 角色图、服装图使用；场景和封面为空 |
| 文件地址 | 文字 | 是 | TOS中的长期地址，不直接存临时下载地址 |
| 原文件名 | 文字 | 是 | 便于追溯；错别字不作为逻辑依据 |
| 宽、高、时长 | 数字 | 否 | 图片记录宽高；视频和音乐记录时长 |
| 内容摘要 | 文字 | 否 | 防止同名文件被错误替换 |
| 是否用于定妆照、是否用于视频 | 真假 | 是 | 明确输入边界 |

### 2.5 用户表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 用户编号 | 文字 | 是 | 服务端内部编号 |
| 微信用户标识 | 文字 | 是 | 服务端通过登录凭证换取；不把会话密钥放小程序 |
| 昵称、头像 | 文字 | 否 | 只有用户授权后保存 |
| 首次登录、最近登录时间 | 时间 | 是 | 登录审计 |
| 是否停用 | 真假 | 是 | 异常账号处理 |

### 2.6 隐私和授权记录表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 记录编号、用户编号 | 文字 | 是 | 关联用户 |
| 授权类别 | 文字 | 是 | 隐私政策、上传本人照片、上传他人照片、生成内容、保存作品 |
| 授权版本 | 文字 | 是 | 记录用户看到的文本版本 |
| 是否同意 | 真假 | 是 | 不同意不能进行相应步骤 |
| 授权时间 | 时间 | 是 | 审计用 |
| 来源设备信息 | 文字 | 否 | 只保留必要信息 |

上传亲友照片不能默认为“已获得肖像授权”。二期应在上传前给出明确提示，并在视频素材需要真人认证时进入专门的授权状态。

### 2.7 制作会话表

“制作会话”就是游客点击“拍同款”后的一次制作记录。

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 制作编号 | 文字 | 是 | 所有上传、任务、作品的主关联 |
| 用户编号 | 文字 | 是 | 归属用户 |
| 模板编号、模板版本编号 | 文字 | 是 | 固化用户当时选择的版本 |
| 景区编号 | 文字 | 是 | 便于作品归档和统计 |
| 当前步骤 | 文字 | 是 | 选模板、待上传、检测中、待看定妆照、待确认视频、视频中、完成、失败 |
| 当前定妆照编号 | 文字 | 否 | 视频提交前展示 |
| 当前视频任务编号 | 文字 | 否 | 用户确认后才有 |
| 是否已确认生成视频 | 真假 | 是 | 防止刷新页面或重复点击提交视频 |
| 创建、修改时间 | 时间 | 是 | 页面恢复和问题排查 |

### 2.8 用户照片和上传文件表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 文件编号 | 文字 | 是 | 统一文件编号 |
| 制作编号、槽位编号 | 文字 | 是 | 一张照片必须明确属于哪一次制作、哪个角色 |
| 用户编号 | 文字 | 是 | 权限控制 |
| 文件类别 | 文字 | 是 | 用户原始人物照、定妆照、视频、封面等 |
| TOS桶标识、文件路径 | 文字 | 是 | 只存文件位置，不存密钥 |
| 原文件名、格式、宽、高、大小 | 文字/数字 | 是 | 上传校验和问题排查 |
| 是否竖屏 | 真假 | 是 | 人物照片不强制9:16，但定妆照和视频必须竖屏 |
| 保存状态 | 文字 | 是 | 上传中、已保存、失败、已删除 |
| 创建时间 | 时间 | 是 | 资产追溯 |

微信 `chooseMedia` 得到的只是临时路径；必须通过上传接口保存后才算用户资产。小程序只拿临时访问地址，不接触TOS密钥。

### 2.9 人脸检测记录表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 检测编号、文件编号 | 文字 | 是 | 一次照片检测对应一张上传文件 |
| 服务名称 | 文字 | 是 | 固定记录为阿里云 FaceBody 人脸检测 |
| 请求编号 | 文字 | 否 | 外部接口排查用 |
| 检测结果 | 文字 | 是 | 通过、没有人脸、多人、质量不足、接口失败 |
| 人脸数量 | 数字 | 是 | 不能只取第一张脸；单人角色要能识别多人照片 |
| 人脸框和质量分数 | 列表/数字 | 否 | 仅保存必要的检测结果 |
| 原始请求时间、完成时间 | 时间 | 是 | 计时和审计 |
| 错误信息 | 文字 | 否 | 给后台排查，不直接展示原始密钥或堆栈 |

阿里云 `DetectFace` 是人脸检测和质量检测，不是身份核验，也不能据此推断用户真实年龄、性别。请求返回的人脸数量必须足以发现多人照片，不能继续固定只返回1张。

### 2.10 定妆照任务表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 任务编号、制作编号 | 文字 | 是 | 任务和制作会话的关联 |
| 模板版本编号、提示词资源编号 | 文字 | 是 | 固化使用哪份模板提示词 |
| 图片服务 | 文字 | 是 | Seedream 5.0 Pro |
| 模型编号 | 文字 | 是 | `doubao-seedream-5-0-pro-260628` |
| 输入文件编号列表 | 列表 | 是 | 用户人物照、场景/角色/服装等实际输入 |
| 提交文字 | 文字 | 是 | 保存替换角色标记后的最终提示词 |
| 输出方向 | 文字 | 是 | 9:16 |
| 输出尺寸 | 文字 | 是 | 1K竖屏 `800x1424` |
| 任务状态 | 文字 | 是 | 未提交、处理中、完成、失败 |
| 返回地址、永久文件编号 | 文字 | 否 | 返回地址24小时后会失效；成功后立即转存TOS |
| 开始、结束时间 | 时间 | 否 | 统计和排查 |

定妆照只是展示和用户资产，不能写入视频任务的参考图列表。Seedream返回的图片链接官方只保留24小时，必须先保存再给小程序展示。

### 2.11 视频任务表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 任务编号、制作编号 | 文字 | 是 | 视频任务唯一关联 |
| 模板版本编号、视频提示词资源编号 | 文字 | 是 | 固化动作文字和模板版本 |
| 图片视频模型 | 文字 | 是 | Seedance 2.0 Mini |
| 模型编号 | 文字 | 是 | `doubao-seedance-2-0-mini-260615` |
| 输出比例 | 文字 | 是 | 固定 `9:16` |
| 输出分辨率、时长 | 文字/数字 | 是 | 每次请求实际发送值；不能只看模板标注15秒 |
| 是否生成声音 | 真假 | 是 | 需要对白/音效/音乐时明确设置；不允许默认猜测 |
| 提交前确认时间 | 时间 | 是 | 没有用户确认就不能提交 |
| 外部任务编号 | 文字 | 否 | 异步提交返回的编号 |
| 外部状态 | 文字 | 否 | 排队、处理中、成功、失败、过期 |
| 永久视频文件编号 | 文字 | 否 | 外部视频链接有效期有限，成功后转存TOS |
| 失败原因、重试次数 | 文字/数字 | 否 | 可控重试，避免重复扣费 |

Seedance 2.0 Mini官方支持9:16，支持0到9张图片的全模态参考，并要求参考图角色为 `reference_image`。同一个请求不能把普通参考图和首帧/尾帧模式混用。二期不把定妆照加入此表的输入列表。

### 2.12 视频参考文件表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 任务编号、顺序号 | 文字/数字 | 是 | 形成最终发送顺序 |
| 来源文件编号 | 文字 | 是 | 用户照片、角色三视图、场景图等 |
| 来源类别 | 文字 | 是 | 真人授权资产、模型可信产物、角色图、场景图 |
| 外部素材编号 | 文字 | 否 | 只有通过素材库后才有 |
| 发送方式 | 文字 | 是 | `asset://编号`或公网地址 |
| 外部素材状态 | 文字 | 是 | 未提交、处理中、可用、失败、过期 |
| 是否实际发送 | 真假 | 是 | 保留最终请求证据 |

这里必须增加“来源类别”和“可用状态”。官方国内文档明确：Seedance 2.0不能直接上传含真人人脸的普通图片/视频；可用路径是同账号近30天可信模型产物、平台虚拟人像，或完成真人认证和授权后的素材。当前代码里“所有原始人脸直接送视频模型”的做法与官方限制冲突，不能作为正式二期方案。

### 2.13 用户作品表

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 作品编号、用户编号、制作编号 | 文字 | 是 | 作品归属和追溯 |
| 模板名称快照、景区名称快照 | 文字 | 是 | 即使模板以后改名，历史作品仍可解释 |
| 定妆照文件编号 | 文字 | 否 | 视频前也可以单独查看 |
| 视频文件编号 | 文字 | 否 | 视频完成后填写 |
| 展示状态 | 文字 | 是 | 只对本人可见、可播放、已删除 |
| 创建时间、完成时间 | 时间 | 是/否 | 作品列表排序 |

作品页只读取作品表和文件表，不重新根据当前模板生成内容，也不因为用户返回首页而重新提交任务。

### 2.14 外部服务配置记录表（只存引用，不存密钥）

| 字段 | 类型 | 必填 | 作用 |
|---|---|---:|---|
| 配置编号、服务名称 | 文字 | 是 | 阿里云人脸、Seedream、Seedance、TOS |
| 环境 | 文字 | 是 | 本地、测试、生产 |
| 账号标签 | 文字 | 是 | 例如“二期测试Seedance账号” |
| 区域、模型编号、桶名/素材组编号 | 文字 | 否 | 记录调用目标，便于核查隔离 |
| 是否启用 | 真假 | 是 | 防止误调用生产资源 |
| 最后核验时间 | 时间 | 否 | 配置巡检 |

AK、SK、API Key、微信密钥等只放服务器环境变量或密钥管理工具，数据库不保存明文。TOS账号和Seedance账号必须分别记录，不能因为都属于同一家公司就共用配置。

## 3. 从页面到数据的实际流程

```text
景区页
  -> 读取景区表
热门模板横向卡片
  -> 读取模板表和封面/示例视频资源
点击“拍同款”
  -> 创建制作会话，固化模板版本和角色槽位
上传人物照片
  -> 每张文件绑定制作编号 + 槽位编号
  -> 人脸检测记录通过后才能进入下一步
生成定妆照
  -> 读取定妆提示词、角色图、服装图、场景图
  -> Seedream 5.0 Pro 1K、9:16
  -> 立即转存TOS，页面展示定妆照
用户点击“下一步生成视频”
  -> 服务端检查是否真的点击确认、素材是否满足Seedance真人素材政策
  -> 读取视频提示词和允许的参考文件
  -> Seedance 2.0 Mini、9:16、实际时长
  -> 轮询外部任务，成功后转存TOS
我的作品
  -> 读取作品表，展示定妆照和视频
```

## 4. 二期接口建议

| 接口 | 作用 | 重要校验 |
|---|---|---|
| `GET /api/v2/scenes` | 获取可展示景区 | 只返回后台真实启用的景区 |
| `GET /api/v2/templates?scene=漓江` | 横向模板推送、筛选、分页 | 不返回未审核模板；热门数没有真实数据就不返回 |
| `GET /api/v2/templates/{编号}` | 模板详情和示例视频 | 返回角色槽位和展示资源，不返回内部密钥或完整提示词 |
| `POST /api/v2/projects` | 点击拍同款，创建制作会话 | 固化模板版本；重复请求不新建相同会话 |
| `POST /api/v2/projects/{编号}/uploads` | 上传并绑定角色槽位 | 校验用户、槽位、格式、大小和隐私授权 |
| `GET /api/v2/projects/{编号}/face-check` | 查看人脸检测结果 | 只返回可读状态，不把阿里云原始密钥信息返回前端 |
| `POST /api/v2/projects/{编号}/portrait` | 提交定妆照任务 | 没有全部合格照片不能提交；不能启动视频 |
| `GET /api/v2/projects/{编号}/status` | 查询定妆照/视频状态 | 查询接口不触发新任务 |
| `POST /api/v2/projects/{编号}/confirm-video` | 用户明确点击下一步 | 只允许在定妆照完成、素材合规时创建视频任务；加重复提交保护 |
| `GET /api/v2/works` | 我的作品列表 | 只返回当前用户作品 |
| `GET /api/v2/files/{编号}/url` | 获取短时播放地址 | 服务器检查归属后再签发 |

## 5. 必须在开发前确认的业务规则

这些不是我替你编的默认值，缺少确认就不应写死：

1. 三个样例最终视频时长到底按15秒，还是按提示词里的9/15/11秒。
2. 游客照片要走“已授权真人素材”入库，还是二期先只允许平台虚拟人像/同账号可信模型产物。普通游客直接上传真人照片不能直接送Seedance。
3. 是否让Seedance自动生成对白、音效和音乐；若否，是否只保留模板音乐后期合成。
4. 道具图片是否真正进入视频请求；官方一次最多9张参考图片，需要先确定每个模板的固定输入清单。
5. 定妆照失败是否允许重新生成、每天/每用户次数和费用由谁承担。
6. 视频失败时是否允许重试、重试次数和是否重新计费。
7. 抽奖、权益、支付、退款规则。当前三份模板没有提供这些规则，数据层只应预留制作编号和作品编号关联，不能凭空建立奖品库存、概率或价格。
