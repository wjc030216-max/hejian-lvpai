# 二期当前业务流程（2026-10-05）

这是本地开发版本。首页直接看模板，漓江、银子岩只作为可选筛选项；模板只展示已提供的真实资料，银子岩暂无模板则显示空状态。

## 游客操作
打开即自动静音播放竖屏模板（上下滑动、点画面暂停/播放、换一批、景区与筛选面板、更多模板）→ 按模板角色上传照片并在同页付款 → 作品。
付款按钮标明开发测试跳过，不调用微信支付，不产生支付扣款。

首页人数、关系、视频类型来自服务端真实模板字段。推荐性别、年龄直接读取基础元数据的 recommendation_persona；“不限”保留匹配，不设主角。人数为同框角色数。每批8条，按本次浏览编号稳定排序，返回保留筛选与位置。同一模板的上传草稿独立保存，已付款作品独立按作品编号打开。

## 后台制作
1. 图片文件检查，按角色绑定照片；多人模式检查所有游客照片；一人体验由游客明确选一个坑位，只检查该照片，其他坑位显示并使用模板人物。阿里云检查单人脸与照片质量，未通过不能创建订单。
2. 确认授权后创建零元开发订单，同时保存模板版本和运行资料快照。重复点击复用同一订单。
3. 按角色编号绑定素材，为游客生成换装参考；一人体验的其余角色直接使用对应模板角色图，不自动复制游客人脸。
4. 使用这些角色资料、场景图和模板目录的“11-定妆照提示词.txt”生成 9:16 定妆照。
5. 定妆照先存入独立 TOS，显示在作品中，然后后台自动提交视频，无需再次确认。
6. 视频输入按同一份角色对应表读取游客原始照片或模板人物、对应造型参考、场景图及模板动作文字。不传定妆照、不生成分镜图片。输出为 9:16。
7. 视频成功后合成配乐并保存作品，不发放抽奖机会。

## 数据与恢复
- 模板目录读取本地 MySQL/JSON；订单、作品、角色、素材、消息及制作任务集中保存在本地 MySQL。旧 SQLite 文件只保留作迁移来源和回查。
- 图片、定妆照、视频任务和各步骤结果保存在 phase2_tasks；角色对应表同时进入作品记录。不再使用 Redis 作为二期制作进度或防重复提交的依据。
- 每个制作会话使用自己的运行编号，角色与视频使用同一份模板快照。
- 定妆照保存失败仅重试保存；提交响应丢失先查询原任务，不能直接再建付费任务。
- 明确失败最多三轮。开发订单最终失败显示未扣款，不虚构退款。
- 编排、定妆照和视频服务均可读取数据库检查点恢复。视频保存云端编号后继续查原任务；下载、合成、上传分别恢复，不重新生成。
- 云端提交响应丢失且无法确认是否受理时暂停自动重发，显示待核实；管理员核实原任务后可关联结果继续。详见 PHASE2_HARDENING_RESULT.md。
- 升级前 Redis 作品只读迁移、保留原记录。历史定妆照归档，不因升级自动补发视频任务。

## 保留待接内容
- 微信真实支付和回调：接口保留返回未接入。
- 当前默认本机开发身份；微信登录与作品归属校验已接入，启用多人微信联调需要配置独立开发小程序凭据。
- 模板资料原有文案和时长矛盾仍由模板负责人确认，不自动编造修改。
