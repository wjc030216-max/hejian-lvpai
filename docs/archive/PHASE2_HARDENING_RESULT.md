# 二期整改结果（2026-10-08）

改动仅在本机开发目录和 aitravel-local-real 容器内实施，没有连接测试服务器或生产服务器，没有新提交收费生成。

## 已落实

| 原问题 | 当前实现 |
| --- | --- |
| 视频合成、上传失败可能重新调用模型 | 提交模型、查询结果、合成、上传分别保存进度；恢复时跳过完成步骤，上传失败保留合成文件 |
| 云端任务号只存在内存 | 提交前记录“正在提交”，收到任务号立即写入 MySQL；服务重启后只查询原任务号 |
| 图片超时后重复请求 | 每个角色造型和定妆照都有固定请求编号；图片服务先保存云端地址，再下载、存储，恢复使用原编号 |
| 定妆照及最新任务索引依赖 Redis | 图片、角色、视频任务及中间结果统一记录在 MySQL；任务类型和制作编号具有唯一约束 |
| 缓存比数据库旧 | 二期新任务直接以 MySQL 为准；Redis 不再决定任务是否新建、是否完成 |
| 不能隔离多人作品 | 新增微信登录、服务端确认身份、作品归属校验；媒体地址限制文件范围和有效期 |
| SQLite 整体记录及全表扫描 | 实际运行切换 MySQL；作品、订单、角色、素材、消息、任务分表，后台按待处理状态和时间查索引 |
| 隧道域名变化后旧素材无法使用 | 本机素材按安装标识和相对路径保存，使用时拼接当前域名 |
| 缺少备份恢复验证 | 新增本地备份脚本；冻结相关写入服务，备份数据库和文件卷，恢复到独立临时库，逐表核对记录数 |

原 SQLite 文件和一期表不删除。历史任务只读导入；缺少可靠执行进度的旧任务标记待核实，不因升级重新生成。抽奖执行代码保持删除状态，历史数据库逻辑只以注释留档。

## 结果未知时的恢复

云端已收到请求、但网络在返回任务号之前断开时，程序无法凭空确认是否成功。现在显示“任务待核实”并停止自动重发，这是防止重复计费的处理分支。

管理员先在云端核实同次请求，再运行以下命令。这些命令只查询原结果，不新建模型任务：

```powershell
# 列出待核实任务
docker exec aitravel-local-real-seeddance-video-1 python -m local.reconcile_task
# 替换为已核实属于同一作品的两个编号
docker exec aitravel-local-real-seeddance-video-1 python -m local.reconcile_task --task 本地任务编号 --cloud-task 原云端任务编号
# 图片先恢复到本项目文件服务，再关联原图
docker exec aitravel-local-real-seedream-1 python -m local.reconcile_task --task 图片任务编号 --image-file-url 已核实的本机素材公网地址
```

恢复记录保存人工核实时间，后台继续原流程。只有云端明确失败才允许新的生成尝试；下载、合成、上传恢复不消耗新的模型生成次数。

## 微信登录与付款

本机继续使用 PHASE2_AUTH_MODE=local，不复用一期登录凭证。多人微信联调时，设置 PHASE2_AUTH_MODE=wechat，并填写独立开发小程序的 WECHAT_APP_ID、WECHAT_APP_SECRET；缺少凭据会拒绝登录，不回退到共同身份。

前端已接入登录、携带凭证、过期后重新登录。真实微信登录需要对应小程序的有效凭据；本轮验证采用模拟官方返回和双用户越权测试，没有声称完成真实微信登录验收。付款按约定保持开发跳过，真实支付接口未接入。

## 备份

在项目根目录的 PowerShell 执行：

```powershell
python server/local/backup_local.py --drill
```

存在执行中的生成任务时拒绝冻结服务。备份位于 local-backups，已排除 Git 和 Docker 构建；脚本结束自动恢复相关服务。云端 TOS 对象本体仍在独立桶中，本脚本备份本地对象记录和文件卷，不修改桶。
